# T3 Code on `mp600-4tb`

Personal Ubuntu desktop, running as `nei` with home `/home/nei`.
Use [app.t3.codes](https://app.t3.codes), account `nei.neto@hotmail.com`, environment `mp600-4tb`, or LAN SSH: `ssh nei@192.168.15.80`.
T3 has this user's privileges and exposes its loopback listener through T3 Connect.

SSH to Cron Data 3 through Tailscale, independently of the corporate VPN:

```sh
ssh cron-data3
```

The alias uses `~/.ssh/id_ed25519_cron_data3` and `/usr/bin/tailscale nc`.

T3's Open in VS Code hostname, `cron-data3-agent.tailb524d8.ts.net`, and the short alias `cron-data3-agent` use the same key and transport but log in as `t3-cardoso-neto` to access T3's repositories.
The `cron-data3` alias remains the `nei` maintenance login.
See [Cron Data 3 access](cron-data3.md#vs-code-from-the-macbook-or-desktop) for account and shared-state details.

## Locations

- Repositories: `~/<org>/<repo>` where organized by owner; older checkouts also live under `~/src/<repo>` and `~/quorum/`.
- Agent configuration: each harness's home directory, such as `~/.claude` and `~/.codex`.
- T3 state and runtime: `~/.t3`; logs: `~/.t3/userdata/logs`.
- Service: user unit `t3code.service`, defined in `~/.config/systemd/user/t3code.service`.
  Linger is enabled, so it runs without an interactive login.
- User tools: `~/.local/bin`; Node selector: `~/.local/opt/node-v24`; npm configuration: `~/.npmrc`.
  Keep npm's global prefix at `~/.local`.
- Scheduled work: user crontab and user systemd timers, including `agent-logs-mp600.timer`.
- Network workaround: `/etc/systemd/system/disable-eee-enp5s0.service` disables Energy-Efficient Ethernet to prevent link flapping.
- Shell history: `~/.bash_eternal_history`; `~/.bash_history` is stale.

Use `systemctl --user` for service control and `t3 connect status` for remote-access diagnostics.
The service pins a Node executable; refresh it with `t3 service update` after changing Node or T3.

Setup history: [mp600-4tb.journal.md](mp600-4tb.journal.md).
