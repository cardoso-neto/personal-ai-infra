# T3 Code on `mp600-4tb`

## Access

- [app.t3.codes](https://app.t3.codes): account `nei.neto@hotmail.com`, environment `mp600-4tb`.
- T3 and agents run as `nei`, home `/home/nei`.
- From the MacBook: `ssh mp600` (also `mp600-4tb`) over Tailscale; `ssh mp600-lan` over LAN.
  Connection addresses, keys, and transports are in the Mac's `~/.ssh/config`.
- From this host, consult `~/.ssh/config` for remote aliases.
  - `ssh genesis` over Tailscale or `ssh genesis-lan`; see [Genesis access](genesis.md#access).
  - `ssh cron-data3`: maintenance login as `nei`, independent of the corporate VPN.
  - `cron-data3-agent` and `cron-data3-agent.tailb524d8.ts.net`: T3/VS Code login as `t3-cardoso-neto`; see [Cron Data 3 access](cron-data3.md#vs-code-from-the-macbook-or-desktop).
  - `ssh ansible-tower-prod`: production EC2 access through Cron Data 3; see [minion access](cron-data3.md#production-aws-access-through-the-minion).
- Tailscale: `tailscale status`; DNS routing: `resolvectl status`.
- Network workaround: `/etc/systemd/system/disable-eee-enp5s0.service` disables Energy-Efficient Ethernet to prevent link flapping.

## T3

- Desktop app: `~/Applications/T3-Code.AppImage`.
  Keep its unversioned filename for updates in place.
- Menu entry: `~/.local/share/applications/t3code.desktop`; icon: `~/.local/share/icons/hicolor/512x512/apps/`.
- AppImage prerequisites and sandbox policy: [setup script](../../../../super-system-stuff/hosts/mp600-4tb/install/t3code-appimage-setup.sh), `/etc/apparmor.d/t3code-appimage`.
  AppImages need FUSE; Ubuntu's user namespace restrictions require this AppArmor policy to avoid `--no-sandbox`.
- State: `~/.t3/userdata`; logs: `~/.t3/userdata/logs`; runtime: `~/.t3/runtime`.
- CLI: `~/.local/bin/t3`; runtime selection: `~/.t3/runtime/service-state.json` and `~/.t3/runtime/versions/`.
- Service definition: `~/.config/systemd/user/t3code.service`.
  Use `systemctl --user` for control and journal access, `t3 service status` and `t3 connect status` for diagnostics.
- Inspect the service definition for its executable and environment before changing runtime paths.

## Updates and jobs

- Updater: `~/cardoso-neto/super-system-stuff/hosts/mp600-4tb/bin/autoupdate.sh`; [source](../../../../super-system-stuff/hosts/mp600-4tb/bin/autoupdate.sh).
  Inspect it for channels, desktop replacement, and restart behavior.
- Schedule: `crontab -l`; updater log: `~/.local/state/autoupdate.log`.
- Other scheduled work: `systemctl --user list-timers --all`.
- Agent log archive: `~/.local/bin/sync-agent-logs-host` -> `~/cardoso-neto/agent-logs/sync-agent-logs.sh`.
  - Units: `~/.config/systemd/user/agent-logs-mp600.timer` and `agent-logs-mp600.service`.
  - Source: `~/cardoso-neto/super-system-stuff/hosts/mp600-4tb/dotfiles/.config/systemd/user/`.

## Other locations

- Repositories: `~/<org>/<repo>`; older checkouts: `~/src/<repo>` and `~/quorum/`.
- Harness configuration: each harness's home directory, such as `~/.claude` and `~/.codex`.
- User tools: `~/.local/bin`; Node selector: `~/.local/opt/node-v24`; npm configuration: `~/.npmrc`.
  Keep npm's global prefix at `~/.local`.
- Shared Claude/OpenAI access: [CLIProxyAPI commands, tunnel, and configuration](cliproxyapi.md).
- Grok: native install in `~/.grok/bin`; `~/.local/bin/grok` links to `~/.grok/bin/grok`.
  - Keep `installer = "internal"` in `~/.grok/config.toml`; the npm installer changes it and creates a second copy.
- Shell history: `~/.bash_eternal_history`.

Historical repairs: [installation journal](mp600-4tb.journal.md).
