# Flow spec

1. Trace the relevant code for existing flows; distinguish proposed changes from current behavior.
2. Sketch minimal types/interfaces and pseudocode showing how components compose and where responsibilities cross boundaries.
3. Show an indented call graph from entry point to effects, including meaningful branches and async boundaries.
4. Surface unresolved decisions; keep prose only where the sketches need explanation.
